## Visual and selector rules

Preserve the light primary `#3a3a8c`, neutral semantic roles, small control heights and restrained borders. Prism's cool-gray numeric direction differs from conventional Tailwind scales; map meaning rather than copying numeric token assumptions. Inter and JetBrains Mono are reference fonts; local fallbacks remain an explicit difference unless assets are supplied. Generated utility strings, hashed asset names and `radix-:…` IDs are unsuitable public component contracts.

Use accessible role/name for interactions, stable feature hooks for owner boundaries, and explicit DOM IDs only where confirmed. Scope repeated filter/legend hooks to their feature. Keep primitives free of fetching/authentication, domain state in feature owners, and third-party editor internals behind adapters. Billing, Stripe, checkout, subscriptions and Clerk are outside this implementation.

## Final implemented scope and remaining visual differences

Team administration is implemented at `/team` with Prism-compatible `roles`, `user`, `groups` and `apikeys` query tabs. Admin navigation replaces the classic-only Users and Roles links; Alerts remains classic-only. Native users, one-time passwords, role creation and full-array privilege edits, typed deletion, OIDC defaults, group mappings and safe role inspection, and API-key creation/copy/deletion use this checkout's backend contracts. Each tab has search and 25-row pagination; users support name/email/method sorting. The community OIDC explanations and status sentences are preserved, including provider-only removal protection, legacy provenance, manual overlaps and sign-in/session refresh wording.

Remaining Team differences: enterprise native-group CRUD and SaaS email invites are out of scope; OAuth users are created by provider sign-in. Creation offers dataset scopes, while existing LLM and unrestricted privileges are displayed and preserved. Forms use native selects and checkbox role lists rather than Prism's comboboxes; row actions are visible keyboard-reachable buttons. A visible Default badge replaces the role asterisk. Header and password warning wording follows this frontend brief, and API-key creation explains that later copying remains available through GET. Root/internal privileges are shown only in existing user data. Visual equality with the original Team screen and interoperability with a real provider have not been established by this implementation; completed validation is recorded separately by the reviewer.

The final captures show the shared 48px header, 192px navigation, 240px Logs field panel, compact summary rows, SQL explorer/editor split, table inventory and split login. Password visibility, reset guidance, SSO navigation, identity, session recovery and build-gated demo behavior are implemented. Logs add column search/selection, sorting, wrapping, edit/clear filter actions, UTC absolute ranges, JSON/CSV export and structured/JSON event details. SQL shares those result controls and starts empty on a live server until a dataset or query is supplied.

Intentional differences remain: only implemented navigation is shown; the login action says “Sign in with SSO”; help points to the administrator; local fonts/icons and some spacing differ; sample and live badges are explicit. Logs default to a one-hour range rather than original ten minutes, use bounded returned-row histogram counts, and place pagination below results. The time editor currently supports UTC only, and SQL has one query tab without chart/view-library/AI panels. Dataset metadata metrics are not invented. Dashboards remain browser-local and cannot claim original server-backed dashboard parity.
